# アルゴリズム仕様

計算規則の正本。アプリケーションの構造・設定は[application-plan.md](application-plan.md)、保存形式は[output-format.md](output-format.md)、演算順と乱数消費を保持する変更の検証は[performance.md](performance.md)を参照する。

## 1. 問題

無向・重みなし・自己ループと多重辺のないグラフの頂点を2群へ分け、次を最小化する。

`score = cut_edges + alpha * (size_a - size_b)^2`

`alpha` の既定値は0.05とし、設定可能にする。Flipでは任意の分割を探索し、空の群も許容する。Swapでは偶数頂点を必須とし、初期状態から両群をn/2頂点に保つためペナルティは0となる。各計測点の現行解と暫定解は共有分割プールへの`SolutionId`参照で保存し、合計スコア・カット数・群サイズ・ペナルティは読み込み時に算出する。

Flipは1頂点反転で近傍数n、Swapは異なる群の1頂点ずつの交換で近傍数n²/4。Swapの中間状態を計測・最良解更新へ露出しない。奇数頂点とSwapの組み合わせは設定検証で拒否する。

入力グラフは、既存のRandom（Erdős–Rényi）とGeometric（単位正方形上の幾何グラフ）の生成をサポートする。グラフ生成シードと探索シードは独立に指定する。Geometricの距離閾値は現行式を維持し、指定次数が境界効果を補正しない生成パラメータであることを明記する。実際の平均次数は保存済み辺リストから算出して表示する。任意形式の外部グラフインポートは今回追加しない。

## 2. 探索手法

| 設定名 | 動作 | パラメータ | 1ステップ |
|---|---|---|---|
| `hc` | 選択したFlip/Swapの全近傍から最良の改善を選択 | 平滑化 | 全近傍走査1回。改善なしで終わる最後の走査も数える |
| `sa` | Flipは頂点、Swapは両群から各1頂点を一様選択し、Metropolis規則で判定 | `temperature >= 0`、平滑化 | 受理・棄却判定1回 |
| `eo` | 頂点適応度を順位付けし、順位rを重みr^(-tau)で選択 | 必須`tau >= 0`、適応度 | 反転または交換1回。常に受理 |
| `eo_sa` | EOと同じ順位選択で手を提案し、SAと同じMetropolis規則で判定（[EO-SA](#eo-saeoの提案とmetropolis判定)） | 必須`tau >= 0`・`temperature >= 0`、適応度 | 受理・棄却判定1回 |

平滑化SAは独立した重複実装を作らず、`sa`と平滑化の組み合わせとして扱う。温度スケジュールは導入せず、固定温度であることをヘルプにも表示する。SAの温度0では厳密な改善のみ受理し、正温度では同点も受理する。

EOの組み込み登録名は`default`・`multiplicative`・`additive`の3種とする。`default`（定義`good_edge_fraction-v1`）は頂点iの同群接続数g_i、異群接続数b_iから`g_i/(g_i+b_i)`をλ0として求め、孤立頂点は1とする。`multiplicative`（定義`multiplicative-v1`、params`{alpha}`、`0.0 <= alpha <= 1.0`）は多数派頂点でλ0×alpha、それ以外でλ0を返す。`additive`（定義`additive-v1`、params`{beta}`、`beta >= 0.0`）は多数派頂点でbeta×λ0、それ以外でbeta×λ0+1を返す。多数派は自群が相手群より頂点数で厳密に大きいことで、同数なら誰も多数派でない。Swapは常に等分割を保つため多数派が存在せず、`multiplicative`は`alpha`によらずλ0と等しくなり、`additive`はλ0の単調増加変換になる（`multiplicative`は`default`と同じ順位になる。`additive`も通常は同じ順位だが、`beta`が小さく`beta*λ0+1`の丸めで値が一致すると同点ブロックが併合され、`beta=0`では全頂点が1つの同点ブロックになる）。paramsは浮動小数点のJSON数値のみを受け付け、整数値・`-0.0`・範囲外の値は拒否する。`good_edge_fraction`・`multiplicative`・`additive`は定義説明に使う名前であり、設定名の別名にはしない。条件に登録名と定義バージョンを残し、説明文字列を各結果に複製しない。`good_edges`・`negative_bad_edges`・候補評価差は組み込まない。`default`の定義は[原論文Sec. III.B](https://arxiv.org/pdf/cond-mat/0104214)に基づく。

適応度の小さい頂点を順位1とする。EOの同点処理は標準順序上のブロックへ重みを平均化する規則（次項）を使い、専用RNGでのシャッフルは行わない。HCの同点改善候補は従来どおり専用乱数（`tie_rng`）で一様選択する。

### EOの選択規則v2

全頂点を`(λ(v), side(v), v)`の昇順で並べた列を**標準順序**とする。λの比較は`f64::partial_cmp`で行い（値は有限、`-0.0`と`0.0`は等しい）、`side(v)`は`state.partition()[v]`（`true`=群A）で、`false`を`true`より先に置く。標準順序上でλが`==`で等しい極大区間を**ブロック**と呼ぶ。

順位1..nに重み`r^(-tau)`を割り当てて累積し、合計で割って`[0,1]`の累積分布`cum`を作る（`tau=0`は一様選択、`tau`が大きいほど順位1に重みが集中する）。同じブロックに属する頂点は、旧`select_eo_rank`と同じ規則で、そのブロックが占める順位区間の重みの合計を頂点数で等分して受け取る（同点群の重みの平均化）。

Flipの選択頂点、およびSwapの1頂点目は、`select_rng`から一様乱数を1個引き、`cum`上で対応する位置のブロックを求め、ブロック内で均等割りした重みに応じたオフセットで標準順序上の頂点を選ぶ。

Swapの2頂点目は、1頂点目を選んだ時点の群所属で決まる反対側の群にだけ条件付けた分布から選ぶ。標準順序のブロックを順に走査し、反対側の頂点を含むブロックだけを対象に、そのブロックの等分後の重みのうち反対側頂点数に比例する分を重みとする。`select_rng`からさらに一様乱数を1個引き、対象ブロックの累積重みで走査対象のブロックを選び、その中の反対側頂点から均等割りしたオフセットで頂点を選ぶ。重みの合計が0になる退化例（極端な`tau`など）では、反対側頂点を含む最初のブロックから一様に頂点を選ぶ。

演算順を含む正確な定義は次のとおり。ブロックは標準順序上の0始まりの位置区間`[s, e)`で表す。

```text
cum:  cumulative = 0.0; for j in 1..=n { cumulative += (j as f64).powf(-tau); cum.push(cumulative) }
      z = cumulative; 各 cum[k] /= z

1頂点目: u = select_rng.gen::<f64>()
      p = cum.partition_point(|c| c <= u).min(n - 1);  [s, e) = p を含むブロック
      lo = (s == 0 ? 0.0 : cum[s-1]);  hi = cum[e-1];  m = e - s;  per = (hi - lo) / m
      off = per > 0.0 ? min(floor(max(u - lo, 0.0) / per), m - 1) : 0;  選択 = 標準順序[s + off]

2頂点目（Swap、o = !side(1頂点目)）:
      反対側頂点を含むブロックごとに c = e - s、c_o = 側oの頂点数、
      W = cum[e-1] - (s == 0 ? 0.0 : cum[s-1])、x = W * c_o / c（この演算順）
      T = x をブロック順に 0.0 から逐次加算;  u2 = select_rng.gen::<f64>()
      T > 0.0: target = u2 * T;  acc = 0.0 から next = acc + x を加算し、最初に target < next となるブロック
               （なければ最後の対象ブロック、acc はその直前の累積値）;
               per = W / c;  j = per > 0.0 ? min(floor(max(target - acc, 0.0) / per), c_o - 1) : 0
      T == 0.0: 最初の対象ブロックで j = min(floor(u2 * c_o), c_o - 1)
      選択 = そのブロック内の側oの頂点のうち標準順序で j 番目
```

RNG消費はFlipが1ステップにつき1回、Swapが1ステップにつき2回（1頂点目用、2頂点目用の順）で、いずれも`select_rng`から引く。EOは同点処理専用RNG（`tie_rng`）を使わない（HCの同点改善候補選択は`tie_rng`のまま維持する）。`cancel.check()`は選択後・適用前に行う。

組み込み適応度（`default`・`multiplicative`・`additive`）は差分更新索引で標準順序を保持する。索引は初期構築で全頂点のλを1回計算し、1手ごとに移動した頂点とその隣接頂点だけを再配置する（Flipは1+deg(v)頂点、Swapは両端点と隣接分の2+deg(a)+deg(b)頂点）。多数派に依存する定義（`multiplicative`の`alpha<1.0`、`additive`）は群サイズの大小関係3通り（群Aが多数派・群Bが多数派・同数）を常に保持し、選択時点の群サイズに応じた状態を使う。Swapは等分割を保つため常に同数状態だけを使う。多数派に依存しない定義（`default`、`multiplicative`の`alpha=1.0`）は状態1つで足りる。登録で置き換えた独自`VertexFitness`はこの索引を使わず、毎ステップ`values()`で全頂点を評価してから標準順序へ整列する。

組み込み経路と、`values()`から標準順序を作って上記の抽選を素朴に行う独立参照実装は、全ステップで選択頂点・状態・乱数列までビット一致する。

アルゴリズムv1（毎ステップ同点をシャッフルして安定ソート）との関係: 1頂点目の選択分布は同一で、Flipの1ステップの挙動は変わらない。Swapの2頂点目は、v1では1頂点目と同じシャッフル結果の順位に条件付けていたため分布が異なり（1頂点目が反対側の頂点と同じ同点ブロックの上位順位を取りやすい）、独立レビューの測定では1ステップの(1頂点目, 2頂点目)の全変動距離がτ=1〜2で約0.02〜0.2、v2の方が貪欲だった。v2のSwapは旧実装（コミット`c0dd61f`、「反対側が出るまで再抽選し、50回で一様にフォールバック」）と、フォールバックを除いて同じ分布である。

tausは非空の有限・0以上の値の配列を必須とし、自動推定を廃止する。Rust APIの単一tauも必須にし、OptionやDefaultで補完しない。`eo + swap + default`を論文に沿う基本構成、`eo + flip`を同じ適応度を反転へ適用する変種と明示する。適応度へバランスペナルティは暗黙に加えない。

`VertexFitness`は現在の状態から全頂点の有限な適応度を返し、小さいほど低適応度とする。同じ状態・パラメータには同じ値を返し、探索状態や順位選択用RNGを変更しない。`FitnessRegistry`で定義の検証・生成処理を登録し、名前・バージョン・正規化済みparamsを解決する。追加定義はRustで実装・登録して再ビルドする。動的ロードや数式評価器は追加しない。キャッシュはジョブが所有し、独自定義に局所更新を要求しない。差し替え例・テスト用定義は配布CLIへ登録しない。

全手法に最大ステップ数を設定し、HCにも上限を適用する。最良解は実スコアが改善したときのみ更新し、同点では先に見つけた解を保持する。「最終解」と「訪問した解のうち実スコアが最良の解」を両方返す。棄却したSA・EO-SAの候補や計測用山登りの解は探索の最良解に含めない。

### EO-SA（EOの提案とMetropolis判定）

`eo_sa`は、EOの順位選択で手を提案し、SAと同じMetropolis規則で受理を判定する。長谷川「Extremal Optimization法とアニーリング法の比較評価に関する再検討」（第14回最適化シンポジウム、2022）の混合アルゴリズムを、平滑化なしでFlip/Swapへ移したものである。論文のパラメータのうち、順位選択の指数bを`tau`、温度（Θ=log10 T）を`temperature`に対応させる。

論文との違いは次の2点である。
- 論文のνは、最初に選んだ都市の2本のパスのうち長い方を除く確率である。Flip/Swapでは頂点（Swapは頂点対）を選ぶと手が一つに決まるので、対応するパラメータを設けない。
- 論文の平滑化（Gu–Huang型の距離変換）は扱わない。重みなしグラフの0/1隣接行列に適用すると、Swapでは目的関数が正の定数倍と定数の和になるので温度の読み替えと等価になり、Flipではそれに加えてバランス項の係数が変わるだけになる。

1ステップの規則は次のとおり。

1. 現在の状態の標準順序から、[EOの選択規則v2](#eoの選択規則v2)で手`mv`を選ぶ。`select_rng`の消費はEOと同じくFlipが1回、Swapが2回で、受理・棄却によらない。独自適応度では、EOと同じく選択のために全頂点の適応度をn回計算し、この時点で適応度の計算回数に数える。
2. `cancel.check()`を行う。中断したステップは、選択用の乱数と、独自適応度では選択のための適応度計算だけを消費する。状態・順位・評価値・適用移動数・評価回数は変えない。
3. 候補の実評価値`next`を差分評価（Flipは`flip_score`、Swapは`swap_score`）で求め、探索の評価回数を1増やす。非有限ならそのジョブを数値エラーで終了する。
4. 探索が保持する現在の実評価値`current`との差`delta = next - current`を求め、SAと同じ式・演算順で判定する：`accept = delta < 0.0 || (T > 0.0 && accept_rng.gen::<f64>() < (-delta / T).exp())`。受理用の一様乱数は、`delta >= 0.0`かつ`T > 0.0`のときだけ1個引く。`T = 0`では厳密な改善だけを受理し、受理用の乱数を引かない。正温度では同点（`delta = 0`）を必ず受理するが、乱数は1個消費する。
5. 受理したら手を適用し、EOと同じ規則で移動頂点と隣接頂点の順位を更新する。`current = next`とし、適用移動数を1増やす。棄却したら状態と順位を変えない。

受理用の乱数`accept_rng`は、他の探索用ストリームと同じ導出元（グラフ内容、近傍方式、探索シード、alpha、手法条件のJSON、適応度の定義バージョン、`algorithm-v1`）と用途ラベル`accept`から導出する。`eo_sa`は`tie_rng`と`smooth_rng`を使わない。選択と受理のストリームを分けるので、`select_rng`の消費は温度によらずEOと同じになる。

初期化はEOと同じで、初期分割、順位の索引（組み込み適応度では初期構築にn回の適応度計算）、`current = score`（評価回数1）を用意する。適応度の登録名・params・定義バージョン・Registryの扱い、組み込み定義の差分更新索引、独自定義の毎ステップ評価はEOと同じである。条件IDとRNGの導出には適応度の定義バージョンを含める。平滑化は受け付けない（`smoothing`の指定は未知フィールドとして拒否する）。計測はEOと同じく実空間だけを扱い、`basin = "both"`は実空間のみと解釈する。

診断値は次のとおり。
- `applied_moves`は受理した手の数、棄却数は`completed_steps - applied_moves`。
- `objective_evaluations_search`は1+ステップ数。
- `fitness_values_computed_search`は、組み込み適応度では初期構築のnに、受理した手ごとの再配置頂点数（Flipは1+deg(v)、Swapは2+deg(a)+deg(b)）を加えた数。独自適応度では選択ごとにn（中断したステップの選択も含む）。

パラメータの端点での振る舞い：
- `tau = 0`では、浮動小数点の丸めを除いてどの頂点も確率1/nで選ばれ、提案の分布がSAと同じになる（Flipは一様な1頂点、Swapは群をまたぐ頂点対がそれぞれ確率4/n²）。ただし乱数の使い方とストリームが違うので、SAとはビット単位で一致しない。
- `(-delta / T).exp()`が常に1.0に丸められるほど温度が大きいとき（例：`T = 1e300`）は、すべての手を受理する。`select_rng`の状態が同じなら、EOと同じ軌跡になる（実際の条件では手法条件がRNG導出に入るので、EOとは別の系列になる）。`temperature`は有限値だけを受け付ける。温度が無限大の場合はEO（`eo`）を使う。
- EOの提案は対称でないので、受理判定を加えても定常分布は温度Tのボルツマン分布にならない。論文と同じく、Hastings補正は行わない。

設定の`taus`と`temperatures`は非空の配列とし、各要素は有限かつ0以上とする。`fitnesses`は省略時に`{ kind = "default" }`一つへ解決する。展開は`taus × temperatures × fitnesses`の直積である。

## 3. 平滑化

次の4種類をHC・SAから指定できる。`k_average`とその公開型・設定・使用例は削除する。EO・EO-SAへのsmoothing指定はnoneを含めてエラーにする。

| 設定名 | 定義・Kの扱い |
|---|---|
| `none` | 元の目的関数 |
| `all_average` | 選択した近傍の全距離1近傍の平均 |
| `random_k_average` | K個の非復元抽出。距離1近傍数Mを超えれば全距離1近傍と必要数の距離2近傍を使用。Kは1以上、上限は距離1と距離2の合計数 |
| `weighted_average` | `w * 全距離1近傍平均 + (1-w) * 元スコア`。`w=min(K,M)/M`、K=0も許可 |

Flipの距離2近傍は異なる2頂点の反転で個数C(n,2)。Swapは各群から2頂点ずつを選んだ交換で個数C(n/2,2)²。元状態・距離1の状態・重複は含めない。頂点番号順の正規な近傍番号を用い、候補状態の全実体化を避ける。

Kの正規化はグラフごとに行い、計画表示で要求値と有効値を示す。正規化後に同じジョブになる重複設定はエラーとし、無断で回数を減らさない。

探索中のランダム平滑化は呼び出しごとに再サンプリングする。SAは受理時の評価値を次の判定まで保持する。HCは現状態と候補を走査時に評価し、選択された候補の評価値を引き継ぐ。確率的評価のHCの改善なし終了は厳密な局所最適性を保証せず、終了理由を`no_sampled_improvement`とする。

## 4. 差分評価

頂点`v`の次数を`d_v`、現在カットされている接続数を`c_v`とすると、Flipのカット数差分は

`Delta C = d_v - 2*c_v`。

群サイズを更新した`(C',t',f')`から、必ず`C' + alpha*(t'-f')^2`を再構成する。`cuts_at[v]`を保持して隣接頂点だけ増分更新し、候補評価は`O(1)`、適用は`O(d_v)`で行う。Swapは交換する2頂点の周辺辺だけを差分更新する。小規模テストでは全再計算と`f64::to_bits()`まで一致させる。

## 5. グラフ生成

Randomは全頂点対を走査する Erdős–Rényi `G(n,p)` とし、`p=expected_degree/(n-1)`。Geometricは`[0,1]^2`へ一様配置し、距離閾値以内を辺とする。指定次数は生成パラメータであり、実平均次数は保存辺リストから算出する。保存グラフは正規化辺リストと内容ハッシュを正本とし、座標や隣接リストの重複保存は行わない。

## 6. 乱数と計測

グラフ生成、初期分割、探索、平滑化、同点処理、EO-SAの受理判定、計測を用途別RNGへ分離し、SHA-256と固定エンディアンで導出する。探索RNGは計測頻度、診断、並列順序の影響を受けない。各保存計測点で現行解と、そこまでの実評価値最小の暫定解を保持し、同一分割は共有プールへ一度だけ登録する。ベイスン計測の解は探索の暫定解に混ぜず、終点分割は保存しない。

## 7. 計算量

全目的関数評価は`O(n+m)`、差分Flip候補は`O(1)`、移動適用は`O(deg(v))`。平滑化なしのHCと実評価ベイスンの距離1全走査は論理的には候補数に比例するが、最良値・選択・同点抽選を変えられないことが整数の下界で分かる候補は計算しない（Swapでは隣接項を除いた差分`g(a)+g(b)`を下界に使う。候補順と同点の乱数消費は全走査と同じ）。SAの`none`は1ステップあたり平均`O(m/n)`、EOは適応度計算と順位抽選のコストを要する。EO-SAはEOの順位抽選に差分評価1回を加え、棄却したステップでは順位を更新しない。距離2を含む平滑化とベイスン計測は設定上限に応じて増加する。
