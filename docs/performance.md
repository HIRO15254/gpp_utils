## 実装方針

- EOの組み込み適応度は、状態が整数で保持している頂点別カット接続数を使う。同群接続数を `degree - cuts` で求め、従来と同じ `good as f64 / degree as f64` を実行する。孤立頂点の値は1。独自の `VertexFitness` は従来の呼び出しを維持する。
- （2026-09-15時点、EOアルゴリズムv1）EOの第1頂点の重みは、ジョブ内で固定の頂点数・tauについて従来の式で事前計算した。Swapの第2頂点は、適格な頂点の最小全体順位で正規化する従来の式を維持した。順位配列は毎回 `0..n` に戻してからシャッフルし、従来の安定ソートを使った。
- （2026-09-25、EOアルゴリズムv2）EOは同点平均化規則へ変更し、組み込み適応度は差分更新索引（`src/solvers/eo.rs`）で順位を保持する。累積分布はジョブ内で1回だけ作り、1手ごとに移動した頂点と隣接頂点だけを再配置する。Swapの第2頂点は対象ブロックを順に走査して厳密な条件付き分布から選ぶ。独自適応度は毎ステップ評価して整列する。計算規則は[algorithms.md](algorithms.md)の「EOの選択規則v2」、ビット一致の基準は`src/solvers/test_reference/eo_v2_reference.rs`。
- SAでは非平滑化の探索評価値を実評価値として再利用し、暫定分割の内容を既存バッファへコピーする。再計算・再確保を減らし、受理判定は変更しない。
- 実評価値のベイスンと非平滑化HCは、候補状態を適用して戻す処理を差分評価へ置き換える。候補順・評価回数・同点抽選を維持し、選択した移動だけを適用する。
- （2026-09-15の高速化）平滑化の内部アルゴリズムは変更しなかった。計測頻度や出力を維持した。この記述は現在の2026-09-25高速化の変更範囲を制限するものではない。

- （2026-09-26）平滑化なしHCと実評価ベイスンの最良改善走査（`src/graph_partition/descent.rs`）は、候補のスコアが整数の差分`s`について`(cut + s) as f64 + penalty`で単調であることを使い、最良値・選択・同点の乱数を変えられないと整数の下界で分かる候補を計算しない（Swapは行ごとに`g(a) + min g(B)`で読み飛ばす）。1回の降下（HCでは1ジョブ）の間、頂点の利得`g(v) = deg(v) - 2 cuts(v)`と利得の水準ごとのビット集合を保持し、`apply_flip`と同じ規則で移動ごとに更新する。ビット集合から取り出した候補は従来の整数条件で再判定するので、計算する候補、その順序、同点の乱数消費は全走査と同じ。診断の評価回数は、読み飛ばした候補を含む論理的な回数を保つ。キャンセルは走査の開始時と論理的な候補1024個ごと（Swapは行の境界で、読み飛ばした行に当たる確認は次に処理する行の前へまとめる）に確認し、キャンセルした走査は評価回数と乱数を進めない。
- （2026-09-26）EOの組み込み適応度の索引は、(ブロック, 側)ごとの頂点ビット集合と、64ブロック単位の合計・非空マスクで順位を引く（Fenwick木を置き換え、更新はO(1)）。各頂点の位置は`first + 2 cuts + side`の行で持ち、`apply_flip`・`apply_swap`と同じ規則で移動した頂点と隣接頂点の行を更新する（状態を読み直さない）。Swapの2頂点目は非空ブロックを標準順序で走査し、条件側の頂点がないブロックは正確に+0.0の寄与として分岐なしで加える（`tau >= 0`で重みが+0.0以上であることに依存する）。ビット集合の密な配置が`max(32 MiB, 8·R·n·⌈n/64⌉)`バイト（Rは順位の数で1または3）を超える場合は、空いた格納枠を使い回す配置へ切り替えてメモリを抑える。
- （2026-09-26）平滑化の評価は全近傍リストと長さMの添字配列を作らない。部分Fisher–Yatesは同じ`gen_range`を同じ順に引き、スレッドごとの恒等配列の上でO(K)で再現してO(K)で戻す（配列の保持は2^22要素まで）。総和は同じ式・同じ順で計算し、距離2は状態を複製せずに整数の差分から求める。平滑化したベイスンの候補は、状態を複製せずに適用・評価・取り消しで評価する（2026-09-25の作業の方式）。
- （2026-09-26）SAは手法の種類を1回だけ判定し、`Engine::advance`が次の計測点までの手順（キャンセル確認、1手、計数、暫定解の更新）を、実評価SAではFlip/Swap専用のループで実行する。Metropolis判定の`(-delta / t).exp()`は、deltaのビット列をキーとする1024要素の直接写像のメモから同じビット列を返す（SAとEO-SA。乱数を引く条件と順序は変えない）。`apply_flip`は隣接頂点の更新を分岐なしで行う。
- （2026-09-25・09-26）グラフは隣接行列のビット表（8 MiB以下、n ≤ 8192）と内容ハッシュのキャッシュを持つ。どちらも保存形式・ハッシュ・公開APIに含めない。
- （2026-09-26）平滑化なしHCの走査データとEOの索引はEngineの手順だけが更新するので、Engineの分割状態は非公開とし、外部からは読み取りだけを許す。

2026-09-15の高速化では公開設定、保存形式、アルゴリズムバージョンを維持した（2026-09-25にEOのアルゴリズムv2と結果JSONの分割表現を意図的に変更）。計算処理と比較テストを別担当に分け、統合時に独立レビューを行う。

## 検証と採用

基準実装をテスト用に凍結し、各変更を個別に照合する。Flip/Swap、孤立頂点、同点多数、極端なtau、温度0、受理・棄却、計測・診断、HCと平滑化を対象とする。基準実装を新実装に合わせて書き換えない。1ビットでも不一致が生じた変更は採用しない。

探索・計測・検証・保存は分けて測る。初回のウォームアップを除き、複数回の中央値を比較する。変更前後で同じベンチマークソース・入力を使い、コンパイルや別のベンチマークを同時実行しない。速度だけでなく結果の署名も照合する。

比較用のEngineとrunnerを `src/solvers/test_reference/` に凍結した。組み込み適応度は旧隣接走査を行うテスト用factoryと比較する。全ステップの状態、評価値のビット列、診断カウンター、3系列それぞれの次の624乱数出力を照合する。完全孤立グラフと完全グラフでも340ステップ・複数シードで比較し、MT19937-64の状態境界をまたぐ。同時に、状態キャッシュの値を辺リストからの独立再計算と比較する。

runnerは全ステップ／疎な記録、診断有無、ベイスン有無について分割・参照・暫定解・浮動小数点ビットを比較する。fixtureが共有する状態管理・平滑化・計測点生成に将来変更を加える場合は、その処理にも独立した比較基準を追加する必要がある。有限個のテストだけを一般的な証明とは扱わず、整数の同値性と浮動小数点・乱数の処理順序をレビューでも確認する。
