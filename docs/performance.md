# 計算結果を維持する高速化

## 比較契約

比較基準はコミット `51577f9`。同じOS・CPU・Rustツールチェーン・Cargo.lockで、全ステップの現行解、暫定解、探索評価値、計測値、終了理由、乱数系列、論理的な診断カウンターを維持する。浮動小数点は許容誤差を使わずビット単位で比較する。分割の登録順と参照も変更しない。

実行時間、試行ID、同じ時刻にキャンセルした場合の到達ステップは一致対象から除く。キャンセル後に最後の確定状態を保存する契約は維持する。異なるOS・CPU・コンパイラ間の浮動小数点一致は、この高速化の保証範囲に含めない。

高速化では乱数生成器、乱数消費条件、候補順、同点処理、浮動小数点の加算・減算順を変更しない。近似関数、fast-math、浮動小数点の並列集約、数学的な式変形による代用は行わない。

## 実装方針

- EOの組み込み適応度は、状態が整数で保持している頂点別カット接続数を使う。同群接続数を `degree - cuts` で求め、従来と同じ `good as f64 / degree as f64` を実行する。孤立頂点の値は1。独自の `VertexFitness` は従来の呼び出しを維持する。
- EOの第1頂点の重みは、ジョブ内で固定の頂点数・tauについて従来の式で事前計算する。Swapの第2頂点は、適格な頂点の最小全体順位で正規化する従来の式を維持する。合計と逐次減算には同じ重みを再利用する。
- 順位・条件付き抽選の作業配列は容量を再利用する。順位配列は毎回 `0..n` に戻してからシャッフルし、従来の安定ソートを使う。
- SAでは非平滑化の探索評価値を実評価値として再利用し、暫定分割の内容を既存バッファへコピーする。再計算・再確保を減らし、受理判定は変更しない。
- 実評価値のベイスンと非平滑化HCは、候補状態を適用して戻す処理を差分評価へ置き換える。候補順・評価回数・同点抽選を維持し、選択した移動だけを適用する。
- 平滑化の内部アルゴリズムは今回変更していない。計測頻度や出力は維持する。

公開設定、保存形式、アルゴリズムバージョンは維持する。計算処理と比較テストを別担当に分け、統合時に独立レビューを行う。

## 検証と採用

基準実装をテスト用に凍結し、各変更を個別に照合する。Flip/Swap、孤立頂点、同点多数、極端なtau、温度0、受理・棄却、計測・診断、HCと平滑化を対象とする。基準実装を新実装に合わせて書き換えない。1ビットでも不一致が生じた変更は採用しない。

探索・計測・検証・保存は分けて測る。初回のウォームアップを除き、複数回の中央値を比較する。変更前後で同じベンチマークソース・入力を使い、コンパイルや別のベンチマークを同時実行しない。速度だけでなく結果の署名も照合する。

比較用のEngineとrunnerを `src/solvers/test_reference/` に凍結した。組み込み適応度は旧隣接走査を行うテスト用factoryと比較する。全ステップの状態、評価値のビット列、診断カウンター、3系列それぞれの次の624乱数出力を照合する。完全孤立グラフと完全グラフでも340ステップ・複数シードで比較し、MT19937-64の状態境界をまたぐ。同時に、状態キャッシュの値を辺リストからの独立再計算と比較する。

runnerは全ステップ／疎な記録、診断有無、ベイスン有無について分割・参照・暫定解・浮動小数点ビットを比較する。fixtureが共有する状態管理・平滑化・計測点生成に将来変更を加える場合は、その処理にも独立した比較基準を追加する必要がある。有限個のテストだけを一般的な証明とは扱わず、整数の同値性と浮動小数点・乱数の処理順序をレビューでも確認する。

## 2026-09-15の測定結果

Windows、Rust 1.97.0、同一マシン、Cargo.lock固定、release（既存のfat LTO・codegen-units=1）。旧実装は `git archive 51577f9` で別ディレクトリに展開し、新旧に同じ `examples/bench_exact.rs` を置いてビルドした。結果はこの環境・条件での実測であり、他の入力の速度保証ではない。

| 対象 | 条件 | 旧時間÷新時間 |
|---|---|---|
| EO Flip | 500/2000頂点、期待次数5/20、250ステップ | 1.70〜2.20倍 |
| EO Swap | 同上 | 1.50〜1.89倍 |
| SA Flip/Swap | 同じグラフ条件、100万ステップ | 条件間中央値1.020倍（約2%短縮） |
| 非平滑化HC Flip | 500頂点、期待次数5/20、最大20走査 | 3.81〜5.44倍 |
| 非平滑化HC Swap | 同上 | 5.61〜13.11倍 |
| 実評価ベイスン Flip | 500頂点、各計測点で最大10走査 | 計測部分3.96〜7.38倍 |
| 実評価ベイスン Swap | 500頂点、各計測点で最大3走査 | 計測部分8.69〜11.93倍 |

グラフシードと探索シードはそれぞれ42/77の直積。SA温度1、EO tau1.5、alpha0.05。各条件はウォームアップ1回、計測5回の中央値（ベイスンFlipの再測定は9回）。初期点・終了点を保存し、通常の探索測定ではベイスンと診断を無効にする。ベイスン測定はSA1万ステップ、診断を有効にして `measurement_ms` を取り出した。`basin_total` は探索・計測・結果構築を含む時間であり、表の計測部分と区別する。

最初の短いSA測定はばらつきが大きかったため、100万ステップへ延長して新→旧の順に再測定した。32条件の速度比は0.999〜1.036倍で、大幅な改善とは扱わない。EO・HC・ベイスンでは重複計算の削減による明確な改善が見られた。検証・JSONシリアライズ・原子的保存も別行で測定するが、保存処理自体の高速化は行っていない。

主測定64条件、長時間SA32条件、HC16条件、ベイスン16条件の新旧結果署名はすべて一致した。実行時間・試行IDを除いたJSONの署名を比較し、さらに単体テストで浮動小数点のビットと各ステップの乱数系列を直接比較した。

再測定例（新旧それぞれのディレクトリで同じコマンドを使用）:

```text
cargo build --release --locked --example bench_exact
cargo run --release --locked --example bench_exact -- --repeats 5
cargo run --release --locked --example bench_exact -- --mode sa --sa-steps 1000000 --repeats 5
cargo run --release --locked --example bench_exact -- --mode hc --case n500 --repeats 5
cargo run --release --locked --example bench_exact -- --mode sa --case n500 --sa-steps 10000 --basin-only --basin-steps 3 --repeats 5
cargo run --release --locked --example bench_exact -- --mode sa --case n500 --neighborhood flip --sa-steps 10000 --basin-only --basin-steps 10 --repeats 9
```

出力はTSV。`compute` は初期化・探索・最終検証を含む `run_one` の時間、`validate` / `serialize` / `atomic_save` はそれぞれ独立した追加測定。後者の保存先は一時ディレクトリで、既存実験データは使用しない。実行時間はベンチマーク内部で測定し、cargoのビルド時間は含めない。
