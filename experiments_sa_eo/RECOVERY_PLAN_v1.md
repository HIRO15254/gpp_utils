# 復旧run計画 v1

2026-09-25に決定した。状態は**未実行**で、利用者の指示を受けてから実行する。実行順は**A → C → B**とする。

旧実行履歴（`data/legacy_archive/`）のうち、前期研究まとめの議論に使う実験を、新形式の`gpp`で作り直す。条件は`AGENTS.md`「実験のベースライン」にそろえる。

## 共通条件

- グラフ、ステップ数、実行シード、alpha、計測はベースラインと同じである。
  - グラフ：18組×s0
  - ステップ数：10^6
  - 実行シード：0〜31
  - alpha：0.05
  - 計測：対数間隔56点で、現行解と暫定解からの実ベイスンを測る
- 格子もベースラインと同じで、Θ=-1.50〜+2.50（81点、T=10^Θ）、τ=0.00〜3.00（61点）である。どちらも0.05刻み。
- 平滑化のKと適応度のα・βは、ベースラインにない軸なので、旧設計にならう。
- B・Cの仕様は`make_recovery_v1.py`が生成する。数値は`make_baseline_v1.py`の定数と式から作り、手で書き写さない。

## 各段階の中身

- **A ベースライン**：`AGENTS.md`「実験のベースライン」の定義そのものである。
  - 旧集計（`agg_steps.csv`、`agg_steps_screen.csv`）には10^6時点の値がある。Aの結果をこれと比べて新実装を確かめてから、CとBの結果を使う。
- **C 適応度（前期まとめテーマ2）**：旧`data/results_sa_eo_screen`の作り直しである。
  - 適応度は次の24種である。
    - default（Aと共通）
    - 乗算型α=0.0〜0.9の10点
    - 加算型β=0、0.5、1.25、1.5、2、3、4、6、8、12、16、24、32の13点
  - 乗算型α=1.0はdefaultと同じ順位になるので入れない。
  - 旧スクリーニングは22系列（乗算型α 0〜1、加算型β 1.25〜32）だった。これに加算型のβ=0とβ=0.5を足している。
    - β=0は、λ0の情報がなくなる端である。
    - β=0.5は、0<β<1の区間の代表である。この区間では、どのβでも同じアルゴリズムになる。
  - 旧スクリーニングのτは0.1刻みだった。今回はベースラインに合わせて0.05刻みにする。
- **B 平滑化（前期まとめテーマ1）**：旧iter6の作り直しである。
  - 平滑化は次の8種である。
    - none（Aと共通）
    - random_k_average（K=1、2、4、8、16、32）
    - all_average（重みw=1の全近傍平均）
  - 旧本走はΘ=-2.0〜+1.0（0.2刻み）とT=0で、Kは1〜16だった。K=32はT=0でしか回していない。
  - 旧解析で求めた最適点は、どの平滑化でもΘ=-0.6〜+0.8にあり、今回の範囲に収まる。
  - all_averageは、重み付き平均の理論を確かめるために入れる。点を間引くとベースラインの刻みとずれるので、理論上のずれがいちばん大きいw=1の1系列を全格子で回す。

## 計画に含めないもの

- **ベースラインの範囲外**：利用者の指示があれば、例外として追加する。
  - Bの旧T=0と、Θ=-2.0〜-1.6。
  - Cの乗算型α=0を、τ=4、5、6、8、12、20へ延ばす分（3,456 run、約2 CPU時間）。
    - 旧スクリーニングでは、α=0だけ最適なτが上端3.0に張りついていた。τ≤3.0では最適点を決められない。
    - 範囲が足りないと分かっているのは、ここだけである。
- **理論で代える**：weighted_averageのw=1/8〜7/8（326,592 run、約258 CPU時間、5.9 GB）。
  - flip近傍では、全近傍平均がf̄=(1-4/n)f+2m/n+4αになる。
  - このため、重みwの平均でのSAは、温度T/(1-4w/n)の平滑化なしSAと同じ探索になる。
  - Θのずれは最大0.012で、刻み0.05の1/4未満である。
- **作り直さない旧実験**：iter8の10^8 SA、順位乖離調査（rankdiv）、較正・一致確認・パイロット類、途中解を保存したstates。
  - statesが不要なのは、新形式が全計測点の現行解と暫定解を保存するからである。

## 実行

```text
python experiments_sa_eo/run_recovery_v1.py --check   # 実行前の確認だけ（計算しない）
python experiments_sa_eo/run_recovery_v1.py           # A → C → B を実行
```

- **実行前の確認**：`run_recovery_v1.py`は計算を始める前に次の3点を確かめ、1つでも違えば止まる。
  - `cargo build --release --locked --bin gpp`で、`gpp`が現在のソースから作られている。
  - 仕様ファイルが生成スクリプトの出力と一致する。
  - `gpp validate`のbatch_idとジョブ数が`STAGES`の記録と一致する。
- **流し方**：各段階を`--rounds`（シードごとに全条件を終えてから次のシードへ進む）で、`data/v1`へ12並列で流す。
  - 途中で止めても、全条件の試行数がシード単位でそろう。
  - 並列数と保存先は、`--threads`と`--root`で変えられる。
  - 一部の段階だけ流す場合は`--stages C,B`のように指定する。順番はA → C → Bのままである。
- **再開**：中断しても、同じコマンドで続きから再開できる。
  - 保存先にその段階のbatchがあれば、`gpp resume`で再開する。書きかけの結果ファイルも回復する。
  - ある段階が失敗や中断で終わったら、後の段階には進まない。
- **ログ**：進み具合（既定では10分ごと）と、失敗したrunは`data/logs/recovery_v1/`に残る。失敗の理由は、段階ごとに最初の3件まで`gpp inspect`で引いて記録する。
- **止め方**：Ctrl+Cを1回押すと、実行中のrunを片付けてから止まる。
- **長時間の実行**：全体で約60時間かかる。
  - エージェントのセッションに依存しない専用のターミナルで実行し、PCをスリープさせない。
  - PowerShellから別ウィンドウで起動する例：`Start-Process python -ArgumentList 'experiments_sa_eo/run_recovery_v1.py' -WorkingDirectory <リポジトリ>`

## 実行後

- **結果の書き出し**：`gpp export --batch <batch_id> --root data/v1 --out <出力先>`で、段階ごとに`runs.tsv`と`traces.tsv`を書き出す。
  - Cのbatchにはdefault列が、Bのbatchにはnone列が含まれるので、比較の基準も同じ表に入る。
- **最初の照合**：Aの10^6時点を、旧集計と同じ条件で比べる。
  - `agg_steps.csv`：SAはΘ≤+0.80、swapEOはτ≥0.60、flipEOは31点
  - `agg_steps_screen.csv`：旧スクリーニングの22系列、τは0.1刻み

## 変更するとき

- 条件を変えるときは、`make_baseline_v1.py`か`make_recovery_v1.py`を直して仕様を生成し直す。
- あわせて、この文書の表と、`run_recovery_v1.py`の`STAGES`（batch_idとジョブ数）を更新する。
- batch_idが変わると、条件IDも変わっている可能性がある。その場合は、再利用する列が一致するかを`gpp plan`で確かめる。
